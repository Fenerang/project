# WebBackup — система резервного копирования веб-приложений

Учебный проект: централизованная система для создания, хранения и восстановления бэкапов веб-приложений (файлы + база данных).

## Возможности

- **Регистрация приложений** — указание пути к файлам и параметров БД
- **Полный бэкап** — архив `tar.gz` с файлами, дампом БД и `manifest.json`
- **Поддержка БД** — SQLite (из коробки), PostgreSQL и MySQL (при наличии `pg_dump` / `mysqldump`)
- **Планировщик** — автоматические бэкапы по cron (APScheduler)
- **Ротация** — удаление старых бэкапов по сроку хранения
- **Восстановление** — откат файлов и БД из архива
- **Веб-интерфейс** — панель управления и REST API

## Быстрый старт

### 1. Установка

```bash
cd new_project
python3 -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
```

### 2. Запуск системы бэкапов

```bash
python run.py
```

Откройте: **http://127.0.0.1:8000**

Документация API: **http://127.0.0.1:8000/docs**

### 3. Демо-приложение (в отдельном терминале)

```bash
python demo_app/app.py
```

Откройте: **http://127.0.0.1:3000** — создайте несколько заметок.

### 4. Регистрация demo в системе

Через веб-интерфейс укажите:

| Поле | Значение |
|------|----------|
| Название | Demo Notes App |
| Путь | `./demo_app` (полный путь от корня проекта) |
| Тип БД | SQLite |
| Подключение | `sqlite:///./demo_app/data/app.db` |

Или скриптом (после запуска `run.py`):

```bash
python scripts/register_demo.py
```

### 5. Создание и восстановление бэкапа

1. Нажмите **Бэкап** у приложения в панели.
2. Архив появится в `data/backups/app_<id>/`.
3. Для восстановления нажмите **Восстановить** у успешного бэкапа.

## REST API (кратко)

| Метод | Endpoint | Описание |
|-------|----------|----------|
| GET | `/api/applications` | Список приложений |
| POST | `/api/applications` | Добавить приложение |
| POST | `/api/applications/{id}/backups` | Создать бэкап |
| GET | `/api/applications/{id}/backups` | История бэкапов |
| POST | `/api/backups/{id}/restore` | Восстановить |
| DELETE | `/api/backups/{id}` | Удалить бэкап |

## Формат cron

Пять полей: `минута час день месяц день_недели`

Пример: `0 2 * * *` — каждый день в 02:00.

## Структура архива бэкапа

```
backup.tar.gz
├── manifest.json    # метаданные
├── files/           # копия файлов приложения
└── database/        # дамп БД (если настроено)
```

## Требования для отчёта / защиты

1. **Цель** — обеспечить сохранность данных веб-приложений при сбоях.
2. **Объект защиты** — файлы приложения и база данных.
3. **Механизмы** — полное копирование, сжатие, планирование, ротация, восстановление.
4. **Демонстрация** — удалить заметку в demo → восстановить из бэкапа → заметка вернётся.
